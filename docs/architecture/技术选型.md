# DevNest 技术选型

> 版本:v1.0  日期:2026-09-01  作者:Ajiejiejie

## 1. 决策背景

DevNest 定位为**后端开发者自用、长期演进、可扩展高性能**的本地单机桌面调试工具,同时作为技术锻炼载体。选型遵循:

- **长期可维护**:优先 LTS 版本与活跃维护的库,避免停更依赖
- **可扩展**:模块化解耦,后续可插拔新增工具模块(Kafka/ES/gRPC...)
- **高性能**:IO 密集场景用虚拟线程,连接池 + 缓存
- **锻炼价值**:覆盖现代 Java 并发、跨语言进程编排、网络编程、分布式模式
- **KISS**:不引入非必要复杂度,自用工具够用为先

## 3. 关键决策详解

### 3.1 Java 21 + 虚拟线程(核心高性能点)

- **场景**:SSH 隧道心跳、HTTP 调试请求、AI 调用均为 IO 密集,虚拟线程在 IO 阻塞时让出载体线程,单机可承载数万并发
- **启用**:SpringBoot 3.2 + `spring.threads.virtual.enabled=true`,Tomcat 请求线程、`@Async`、`ScheduledExecutorService` 自动虚拟线程化
- **锻炼价值**:现代 Java 并发,告别手撸线程池调参

### 3.2 mwiede/jsch 0.2.x 替换原版 JSch 0.1.55

| 维度 | jcraft/jsch 0.1.55 | **mwiede/jsch 0.2.x** |
|---|---|---|
| 维护状态 | 2018 年停更 | 活跃维护 |
| API 兼容 | 基线 | **完全兼容**,改 groupId 即可 |
| 端口转发 bug | 有已知问题 | 已修复 |
| 安全更新 | 无 | 跟进最新 SSH 算法 |
| 迁移成本 | - | 极低(改 pom 坐标) |

```xml
<dependency>
    <groupId>com.github.mwiede</groupId>
    <artifactId>jsch</artifactId>
    <version>0.2.17</version>
</dependency>
```

### 3.3 H2(dev)+ MySQL(prod)双 profile 配置库

- **角色澄清**:配置库存 DevNest 自身的配置/日志(A/B 类数据),**不是**用户业务数据(C 类)。业务数据源是运行时动态创建的独立连接池,二者完全隔离
- **dev profile**:H2 文件模式(`~/devnest/devnest.mv.db`),MySQL 兼容模式,免安装秒级启动
- **prod profile**:本地 MySQL(`jdbc:mysql://localhost:3306/devnest`),自用可任意客户端查配置/日志
- **切换**:启动参数 `--spring.profiles.active=prod`,代码零改动(JPA 屏蔽差异)
- **Flyway 统一迁移**:H2/MySQL 共用 SQL 脚本(H2 MySQL 模式兼容)

### 3.4 Resilience4j 替代手写重连

用户原型代码手写了 `MAX_RETRIES + RETRY_INTERVAL_MS` 重试循环。新架构改用 Resilience4j:

- `Retry`:指数退避重试(SSH 会话连接)
- `CircuitBreaker`:连续失败熔断,避免雪崩
- `TimeLimiter`:SSH 连接超时控制
- 集中配置、可观测、与 Spring 生态集成

### 3.5 Caffeine 缓存

- 缓存库表元数据(`information_schema` 查询结果),避免二期 AI-SQL/树形展开反复查询
- 缓存连接元信息(端口映射状态)
- TTL 失效 + 容量上限,内存安全

### 3.6 MapStruct DTO 映射

- 实体 ↔ DTO 转换编译期生成,无反射开销
- 避免手写 getter/setter 拷贝样板
- 与 Lombok 协同(注意 Lombok 版本 ≥ 1.18.20)

### 3.7 AES 加密 + 密钥管理

- 算法:AES-256-GCM(带认证标签,防篡改)
- 密钥派生:首次启动生成随机主密钥 → 用**机器 ID(MAC + CPU 序列)派生**的二级密钥加密主密钥 → 主密钥加密存储到本地密钥文件
- 敏感字段(SSH 密码、数据库密码、Redis 密码)入库前加密,出库后解密,前端只接收脱敏 `********`
- 详见 [数据模型.md](数据模型.md) §4 加密字段

### 3.8 WebSocket 终端流(二期核心)

- SSH 交互式终端的 IO 是双向流(键盘 stdin → 远端,远端 stdout → 屏幕),HTTP 请求-响应模型不匹配,用 SpringBoot 原生 WebSocket(不引 STOMP,自用工具够简单)
- 后端每个终端标签一个 WebSocket Session,绑定一个 JSch ChannelShell,IO 互转;前端 xterm.js 直连
- SFTP 走 REST(文件操作非流式,大文件分块),避免与终端流共用通道阻塞
- 心跳:WebSocket ping/pong 检测终端连接活性,复用隧道重连机制

## 4. 替代方案对比记录

| 决策项 | 已选 | 备选 | 否决理由 |
|---|---|---|---|
| 配置库 | H2 + MySQL 双 profile | 纯 H2 | 自用机已装 MySQL,生产用 MySQL 方便离线查 |
| 配置库 | H2 + MySQL 双 profile | 纯 MySQL | 违反双击启动,开发期依赖外部 |
| SSH 客户端 | mwiede/jsch | Apache MINA SSHD | API 重写,迁移成本高 |
| SSH 客户端 | mwiede/jsch | jcraft/jsch 0.1.55 | 停更,有 bug |
| 降级容错 | Resilience4j | Hystrix | Hystrix 已停止维护 |
| 降级容错 | Resilience4j | 手写重连 | 不可观测、易出错 |
| ORM | JPA | MyBatis-Plus | JPA 抽象更高,跨库(H2/MySQL)兼容好;MyBatis-Plus 也可,但 SQL 写死方言 |
| HTTP 客户端 | OkHttp3 | Spring HttpClient | OkHttp 拦截器/连接池更成熟,练手价值高 |
| 桌面壳 | Tauri 2 | Electron | Electron 体积大(100MB+),Tauri 体积小(10MB 级)且 Rust 侧能做重活 |
| 状态管理 | 组合式函数 | Pinia | 工具型应用状态简单,避免过度设计 |
