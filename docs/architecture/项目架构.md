# DevNest 项目架构

> 版本:v1.0  日期:2026-09-01  作者:Ajiejiejie

## 1. 整体架构

双层职责隔离,所有内核逻辑在 SpringBoot,前端纯 UI。

```
┌──────────────────────────────────────────────────────────┐
│  Tauri 桌面壳(Vue3 + Rust)                              │
│  └ 纯 UI 展示 + 用户交互,无业务逻辑                       │
│     └ HTTP/WebSocket(127.0.0.1:8080) ↘                  │
└──────────────────────────────┼──────────────────────────┘
                               │ 仅本机回环
┌──────────────────────────────┼──────────────────────────┐
│  SpringBoot 内核(Java 21 + 虚拟线程)                    │
│                                                            │
│  业务模块(各独立,实现 ToolModule SPI):                  │
│  ┌─────────┐ ┌───────────┐ ┌──────────┐ ┌──────────┐    │
│  │ tunnel  │ │ module/   │ │ module/  │ │ module/  │     │
│  │ SSH底座 │ │ console   │ │ db       │ │ redis    │     │
│  │ (一期)  │ │终端+SFTP │ │ 数据库   │ │ Redis    │     │
│  │         │ │ (二期)    │ │ (三期)   │ │ (四期)   │     │
```

## 2. 分层职责

| 层 | 包 | 职责 | 不允许 |
|---|---|---|---|
| 表现层 | `api` | Controller、DTO、参数校验 | 业务逻辑、直接访问实体 |
| 业务层 | `module/*`、`tunnel` | 业务编排、状态机、降级 | DB 细节、HTTP 细节 |
| 基础设施 | `core`、`common` | 配置库、加密、异常、日志、生命周期 | 业务逻辑 |
| 数据层 | `core/persistence` | JPA Repository、实体 | 业务规则 |

依赖方向:`api → module → core/common`。禁止反向依赖、禁止跨模块横向依赖(除非经 core 抽象)。

## 4. ToolModule SPI(扩展点)

新增工具模块(Kafka/ES/gRPC)只需实现接口 + 注册,不动其他代码:

```java
public interface ToolModule {
    String name();                    // 模块标识(唯一)
    String displayName();             // 中文显示名
    void onStart(ToolContext ctx);    // 模块初始化
    void onShutdown();                // 资源释放
    boolean isEnabled();              // 是否启用(AI 开关等)
}
```

`ToolModuleRegistry` 通过 Spring 自动收集所有实现,启动时统一 `onStart`,关闭时统一 `onShutdown`,与 `ResourceRegistry` 协同优雅释放。

## 5. 数据隔离(配置库 vs 业务数据源)

DevNest 里有三类数据,角色完全不同,必须隔离:

| 类别 | 例子 | 归属 | 连接方式 |
|---|---|---|---|
| **A 配置数据** | SSH 跳板、数据源连接信息、HTTP 模板、AI 配置 | DevNest 自身 | 配置库固定 DataSource(SpringBoot 启动即就绪) |
| **B 运行日志** | SQL 执行日志、HTTP 请求日志 | DevNest 自身 | 配置库同库,或 Logback 文件 |
| **C 业务数据** | 用户的业务 MySQL 库表、Redis 的 key、内网接口 | 不属于 DevNest | 运行时动态创建 DataSource,用户操作时建/销毁 |

**隔离实现**:
- 配置库:1 个固定 `DataSource` Bean,SpringBoot 管理,HikariCP 池
- 业务数据源:N 个动态 `HikariDataSource`,用户在"数据源管理"页添加时创建,退出/删除时销毁
- 代码层用 `AbstractRoutingDataSource` 或独立 Bean 隔离,事务不串

## 6. 资源生命周期

- **配置库连接**:随 SpringBoot 生命周期,优雅关闭钩子释放
- **SSH 隧道**:用户启动时建立,程序退出/用户停止时销毁。绑定隧道的数据源,隧道停止自动标记断开
- **业务数据源**:用户添加时建池,用户删除/程序退出时销池
- **AI 客户端**:懒加载,失效自动禁用

**统一释放**:`ResourceRegistry` 注册所有 `AutoCloseable` 资源,`@PreDestroy` 时逆序释放,确保端口/连接不泄漏。

## 7. 优雅关闭机制

Tauri 关闭 → SIGTERM SpringBoot sidecar 进程 → JVM `ShutdownHook` 触发 → `ResourceRegistry` 逆序释放:

1. 停止接受新请求(Tomcat graceful)
2. 销毁所有终端会话/SFTP Channel(`ConsoleSessionManager.closeAll()`)
3. 销毁所有 SSH 隧道(`SshTunnelManager.stopAll()`)
4. 销毁所有业务数据源池
5. 关闭配置库连接池
6. 关闭 Caffeine/Resilience4j 后台线程

## 8. Tauri ↔ SpringBoot 通信

- **拉起机制**:Tauri `sidecar` 配置,启动时 spawn `java -jar devnest-backend.jar --spring.profiles.active=prod`
- **就绪检测**:Tauri 启动时轮询 `GET /actuator/health`,200 后渲染主界面,期间显示 loading
- **关闭**:Tauri 窗口关闭事件 → `POST /actuator/shutdown`(SpringBoot 端点)→ JVM 钩子触发;超时则 SIGTERM
- **通信**:HTTP `127.0.0.1:8080`,无跨域,无浏览器限制

## 9. 一期打包链路验证(前置风险)

一期就跑通最小 sidecar 链路,避免五期才发现打包问题:

1. 空 SpringBoot(fat-jar)→ Tauri `src-tauri/binaries/` 内嵌
2. Tauri `tauri.conf.json` 配 sidecar
3. 双击 exe → Tauri spawn jar → 轮询 health → 显示 loading → 就绪渲染
4. 关闭窗口 → shutdown 端点 → JVM 钩子

验证通过后再填业务逻辑,风险最低。
