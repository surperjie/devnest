# 文档地图

文档按「**回答什么问题**」分四层，**每层有唯一权威文档** —— 避免同一个问题在多处给出不同答案。

---

## 四层体系

| 层 | 回答的问题 | 权威文档 |
|---|---|---|
| **L0 需求** | 要做什么 | [requirements/需求.md](https://github.com/surperjie/devnest/blob/main/docs/requirements/需求.md) |
| **L1 现状** | 现在是什么样 | [架构文档](https://github.com/surperjie/devnest/blob/main/docs/architecture/20260910_架构文档.md)（机制） · [当前实现能力清单](https://github.com/surperjie/devnest/blob/main/docs/architecture/20260910_当前实现能力清单.md)（可用性） |
| **L2 演进** | 怎么走 | [架构演进路线](https://github.com/surperjie/devnest/blob/main/docs/architecture/20260910_架构演进路线.md)（战略） · [目标架构落地路线图](https://github.com/surperjie/devnest/blob/main/docs/architecture/20260910_目标架构落地路线图.md)（执行） |
| **L3 目标** | 要去哪 | [目标架构 v2.0](https://github.com/surperjie/devnest/blob/main/docs/architecture/20260910_目标架构_v2.0.md) |

### L1 两份文档怎么分工

- **架构文档**回答「机制是怎么设计的」—— 描述设计意图与实现方案；
- **当前实现能力清单**回答「现在到底有什么能用」—— 逐模块判定 ✅ / ⚠️ / ❌。

典型差异：架构文档会说"声明了 3 个 Caffeine 缓存"，而能力清单把它标为 ⚠️ 半实现 —— 因为**没有任何业务代码使用**。**「代码里有」不等于「功能能用」。**

### L2 两份文档怎么分工

- **架构演进路线**回答「架构上必须发生什么」—— 定义 S1→S2→S3 的阶段边界与每阶段的**架构义务**（战略）；
- **落地路线图**回答「具体怎么做、什么顺序、怎么验」—— P0–P5 的**任务 / 落点 / 门禁 / 验收 / 风险**（执行）。

**战略不写任务，执行不重述终态。**

## 权威性约定

同一问题在多份文档里出现不同结论时：

| 问题类型 | 以谁为准 |
|---|---|
| 机制如何设计 | [架构文档](https://github.com/surperjie/devnest/blob/main/docs/architecture/20260910_架构文档.md) |
| 某个能力是否可用 | [当前实现能力清单](https://github.com/surperjie/devnest/blob/main/docs/architecture/20260910_当前实现能力清单.md) |
| 演进阶段与阶段义务 | [架构演进路线](https://github.com/surperjie/devnest/blob/main/docs/architecture/20260910_架构演进路线.md) |
| 终态设计 | [目标架构 v2.0](https://github.com/surperjie/devnest/blob/main/docs/architecture/20260910_目标架构_v2.0.md) |
| 执行计划、阶段顺序与门禁 | [目标架构落地路线图](https://github.com/surperjie/devnest/blob/main/docs/architecture/20260910_目标架构落地路线图.md) |
| 数据表结构 | **Flyway 脚本**（`backend/devnest-boot/src/main/resources/db/migration`） |
| 接口行为 | **实际代码** |
| 怎么跑、怎么排障 | 本 Wiki |

## 约定

- 新增文档使用统一命名：`YYYYMMDD_主题.md`
- **新增任何架构文档后，必须同步更新 [`docs/README.md`](https://github.com/surperjie/devnest/blob/main/docs/README.md) 索引，并明确它在四层体系中的位置与权威性。**
- Wiki 只做导航与操作手册，**不复制 `docs/` 的权威结论**；源文件在 `docs/wiki/`。
