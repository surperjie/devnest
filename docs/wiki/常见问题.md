# 常见问题

## 开发环境

### `mvn` 一跑就报 Java 版本不对

后端要求 **JDK 21**。本机默认 `JAVA_HOME` 若是 1.8，**不要裸跑 `mvn`**：

```powershell
# 方式一：临时切
$env:JAVA_HOME = 'C:\path\to\jdk-21'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
java -version   # 确认是 21
```

```powershell
# 方式二：用仓库脚本（自动定位 JDK 21）
.\scripts\start-backend.ps1
```

### 构建报找不到 `com.dameng:DmJdbcDriver18`

达梦驱动**不在 Maven Central**，仓库内置在 `backend/lib/`。本地 `~/.m2` 里没有时手动装一次（CI 每次都做）：

```powershell
cd backend
mvn install:install-file "-Dfile=lib/DmJdbcDriver18-8.1.3.140.jar" "-DgroupId=com.dameng" -DartifactId=DmJdbcDriver18 -Dversion=8.1.3.140 -Dpackaging=jar -B -q
```

### 集成测试被跳过

Testcontainers 需要 **Linux Docker**。本机没有 Docker 时相关用例显式 skip（不是静默通过），其余测试照常执行。CI 上跑在 `ubuntu-latest`，是真跑的。

## 运行期

### 手动启动后端，中文全是乱码

后端日志按 **UTF-8** 输出（JDK 18+ 默认），而 Windows 简体控制台默认按 **GBK（代码页 936）** 解码，于是中文变成 `鏃犻渶...` / `锟斤拷`。

用仓库脚本（先切 UTF-8 再启动）：

```powershell
.\scripts\start-backend.ps1
```

或手动先切代码页：

```powershell
chcp 65001
.\resources\jre21\bin\java.exe -jar .\resources\devnest-boot.jar --spring.profiles.active=dev
```

> UI 内部拉起的后端已由前端直接落盘 UTF-8 文件 `%TEMP%\devnest-backend.log`，不受此问题影响。

### UI 拉起的后端控制台闪一下就没 / 一直 Network Error

历史根因：Tauri 打包路径带 `\\?\` verbatim 前缀，`java -jar` 无法打开该形式的 jar，进程秒退。

已在 `frontend-ui/src-tauri/src/lib.rs` 修复：传给 java 前还原为普通 Win32 路径，并同时：

- 后端进程不再弹独立控制台窗口（`CREATE_NO_WINDOW`）；
- 后端日志重定向到 `%TEMP%\devnest-backend.log`（UTF-8）；
- UI 启动流程日志在 `%TEMP%\devnest-app.log`。

排障时先看这两个日志的尾部。

### 启动报 `NoClassDefFoundError: sun/misc/Unsafe` / 「Unexpected AOP exception」

`jlink` 裁剪出的 `jre21` 缺了 `jdk.unsupported` 模块 —— Spring AOP（CGLIB / Objenesis）依赖 `sun.misc.Unsafe`。

模块清单的唯一来源是 `scripts/build-jre.ps1`，本地与 CI 共用，**不要在别处复制这份清单**。CI 里还有一步「用内嵌 JRE 启动后端的冒烟测试」专门守这个坑。

### 端口 38080 被占用

桌面版会**弹窗明确提示**，不会静默失败。开发时换个端口：

```powershell
mvn spring-boot:run -Dspring-boot.run.profiles=dev -Dspring-boot.run.arguments=--server.port=38081
```

### 数据存在哪 / 怎么重置

| 环境 | 位置 |
|---|---|
| 开发（`spring-boot:run`） | `<工作目录>/data/devnest-dev.mv.db` |
| 桌面安装版 | `%LOCALAPPDATA%\DevNest\data\devnest.mv.db` |
| 流水线工作区 | `%LOCALAPPDATA%\DevNest\data\pipeline\` |
| 加密主密钥 | `%USERPROFILE%\.devnest\master.key` |

重置 = 关掉应用后删除对应 `.mv.db`（表结构会在下次启动时由 Flyway 重建）。

> 主密钥丢了，之前用 `CryptoService` 加密过的配置（如跳板机密码）就解不开了。

## CI 与门禁

### 每次提交都在打安装包，太慢

已改：**日常 push 只跑质量门禁**，安装包改由 `v*` 标签或手动触发产出。详见 [CI 与发布](CI与发布)。

### 同一次提交，`dev` 上绿、`main` 上红

这是**基线过远**：把 `dev` 快进合并进 `main` 时，`github.event.before` 还停在几十个提交之前，"本次改动"被算成了"整个分支历史"，增量门禁退化成存量全量门禁（存量本来就只有 ~22%，必然红）。

增量门禁脚本已内置**基线过远保护**：提交跨度或改动文件数超阈值时自动回退到 `HEAD~1` 并打印 `::notice::`。详见 [质量门禁](质量门禁) §2。

### 覆盖率门禁红了，怎么看哪里没覆盖

```powershell
cd backend
mvn -B verify                      # 先产出 jacoco.xml
cd ..
.\scripts\check-incremental-coverage.ps1 -BaseRef origin/dev -ShowDetail
```

`-ShowDetail` 会打印每个文件的未覆盖行号。

**只补测试，不要为了过门禁把代码改成注释或加 `@Generated`** —— 那等于把约束变成愿望。

### 门禁说「无判定对象，按通过处理」

本次改动只碰了注释 / 空行 / import / 测试代码 / 纯配置，没有可执行行需要判定。这是预期行为。

### 门禁列出「N 个改动文件未纳入判定」

这些文件所在的模块本次**没有产出覆盖率报告**（通常因为该模块一个测试都没有）。门禁对它们没有约束力，脚本只是把它显式报出来，不再静默掩盖。根治办法是给这些模块补测试。

### 漏洞门禁显示「未执行」

仓库未配置 `NVD_API_KEY` secret。见 [CI 与发布](CI与发布) §4。

### CI 没有被触发

按顺序检查：

1. 分支是不是 `main` / `dev`；
2. 改动是否命中 `paths`（`backend/**`、`frontend-ui/**`、`scripts/**`、workflow 文件本身）；
3. 只改了 `docs/`、`README.md` 之类的路径 —— **不触发是预期行为**。

## 文档与协作

### 两份文档说法不一致，信哪个

见 [文档地图](文档地图) 的「权威性约定」表。核心原则：**每个问题只有一份权威文档**。

### Wiki 怎么改

Wiki 源文件在仓库 `docs/wiki/`，**不要直接编辑 GitHub 上的 Wiki 页面**（下次发布会被覆盖）。改完提 PR，合并后运行：

```powershell
.\scripts\sync-wiki.ps1
```
